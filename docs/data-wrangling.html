4  Data Cleaning

4.1 Learning objectives

By the end of this chapter, you should be able to:

  • explain what data cleaning is and what it is intended to achieve;
  • turn observations from the import chapter into a short cleaning plan;
  • rename awkward columns with rename();
  • change a date column to the correct type with mutate() and dmy();
  • inspect and handle missing values;
  • identify and remove a confirmed duplicate row; and
  • save a clean CSV without overwriting the imported source.

4.2 What is data cleaning?

Data cleaning is the process of identifying, investigating, and correcting problems that could make an analysis inaccurate, confusing, or difficult to reproduce. Common problems include unclear column names, incorrect types, missing information, inconsistent categories, and duplicated records.

The goal is not to make a dataset look perfect or to remove every unusual value. The goal is to produce a table that is fit for the reporting task:

  • each row and column has a clear meaning;
  • values are stored in types appropriate for their meaning;
  • missing and repeated records have been investigated;
  • every change is supported by evidence and recorded in code; and
  • the original source remains unchanged so the work can be checked and rerun.

What counts as “clean” depends on the question. A missing value that prevents one analysis may be acceptable for another. Cleaning therefore requires judgment and source knowledge, not just a list of functions.

Goal for this chapter

We will turn the deliberately imperfect 2025 file into a reproducible, analysis-ready table while preserving the imported CSV. Every change will respond to a problem observed in Chapter 3.

4.3 Continue with the imported table

Chapter 3 imported gpfg_messy.csv as gpfg_raw. Most of the table arrived correctly: the amounts and percentages are already numeric, and the category values are consistent. We only need to solve four visible problems:

  1. a few column names are awkward;
  2. the reporting date is stored as text;
  3. one incomplete row does not describe a holding; and
  4. one complete row has been repeated.

This smaller set of problems lets us practise a cleaning workflow without changing every part of the data at once.

4.5 Rename the awkward columns

Use rename() with new_name = old_name. An old name containing spaces needs backticks:

gpfg <- gpfg_raw |>
  rename(
    year = Year,
    report_date = `Report Date`,
    company = `Company Name`,
    market_value_nok = `Market Value NOK`
  )

4.6 Convert the date type

The values in report_date use day-month-year order, such as 31/12/2025, but R imported the column as <chr> text. The data source tells us what the order means.

Use mutate() to change the existing column. Its basic form is mutate(column = calculation): the name on the left of = identifies the column to create or replace, and the expression on the right produces its values. mutate() keeps the other rows and columns. Here, dmy() means day, month, year:

gpfg <- gpfg |>
  mutate(report_date = dmy(report_date))

Confirm the date order

Do not guess whether 03/04/2025 means 3 April or March 4. Check the source documentation. Use dmy() for day-month-year, mdy() for month-day-year, or ymd() for year-month-day.

4.7 Check missing values

R represents unavailable information with NA. A missing value differs from zero: zero is a known amount, while NA means the value is unavailable.

How filter() works

filter() is a dplyr function that keeps rows where a condition is TRUE:

table |>
  filter(condition)

It selects rows; it does not change column names or values. If the result is only printed, the original object remains unchanged. If the pipeline is assigned back to an object with <-, that object is updated to contain only the kept rows.

The conditions used in this chapter are:

Condition Meaning
is.na(company) The company value is missing
!is.na(company) The company value is not missing
n > 1 The count is greater than one
company == "3P Learning Ltd" The company equals this exact text

! means “not,” > means “greater than,” and == tests whether two values are equal. A single = has a different role: it names arguments and options inside functions.

First use is.na() inside filter() to display rows with a missing company name. Because this result is not assigned, it does not change gpfg:

gpfg |>
  filter(is.na(company))

The result contains one deliberately incomplete row. It has a year and date but no company, country, industry, or market value, so it cannot represent the holding described by the data dictionary. After inspecting the whole row, remove it:

gpfg <- gpfg |>
  filter(!is.na(company))

This time the result is assigned back to gpfg, so the working object now keeps only rows whose company is not missing.

Never remove every row containing NA automatically. In another dataset, a missing value may be expected or may require more reporting. Here the decision is justified because the entire supposed holding is incomplete.

4.8 Check duplicate rows

The file should contain one row per reported holding. count(column1, column2) returns one row for each observed combination and creates n, the number of matching source rows. Use it to find possible repetition across company, country, and industry:

gpfg |>
  count(company, country, industry) |>
  filter(n > 1)

Use the result to identify which records need inspection in the original table:

gpfg |>
  filter(company == "3P Learning Ltd")

The two complete rows are identical. distinct() keeps unique rows. With no column names inside the parentheses, it compares every column and keeps each complete row once:

gpfg <- gpfg |>
  distinct()

A repeated company name is not always a duplicate. The decision depends on the meaning and values of the complete row.

4.11 Takeaways

Function or idea What it does
rename(new = old) Gives selected columns clearer names
mutate() Creates or changes columns
dmy() Converts day-month-year text to a date
is.na() Identifies missing values
filter() Keeps rows where a condition is true; assignment saves the subset
! Means “not” inside a logical condition
count() Counts repeated combinations
distinct() Keeps each complete row once
write_csv() Saves a tibble as a new CSV file
Want more control?

Real reporting data may contain many date formats, number symbols, or text inconsistencies. Begin with the four problems in this lesson. The official dplyr reference and lubridate reference provide additional tools when another dataset genuinely needs them.
